# Veritas 1.5 — Release Notes

**Milestone:** the audit-driven hardening wave (Veritas 1.5) — every bug, unsoundness and
missing capability from the `veritas1.1` audit plus the next horizon of usability.
Package version is **2.1.0** (the repository's own numbering continued); the milestone name
in docs and announcements is **Veritas 1.5**.

## Phase 0 — soundness regressions fixed at `d34fcd27`

- **`quad_form_split` (indefinite quadratic forms) was mathematically unsound.** The
  contractor registered two sign-flipped PSD constraints (`||L₋ᵀx||² ≤ −rhs`), which are
  impossible over the reals and refuted every feasible box, producing false `UNSAT` verdicts.
  It now encodes the difference-of-convex form `||L₊ᵀx||² − ||L₋ᵀx||² ≤ rhs` with only sound
  interval arithmetic: outward-rounded `Lᵀx` products, a forward interval check, and the DC
  relaxation `||L₊ᵀx||² ≤ rhs + max_D ||L₋ᵀx||²` (`≥` dually). `evaluate.py` and the SMT
  certificate renderer now handle `quad_form_split` too (they previously returned
  `INCOMPLETE`), so indefinite-covariance portfolio schemas verify correctly.
- **The quadratic contraction was computed against `Lx` instead of `Lᵀx`** (both in Python
  and Rust) — the wrong quadratic form entirely. Fixed; regression test added.
- **The Rust Eq-quadratic import sample was unsound**: the "narrow to the sampled feasible
  window" logic could exclude genuinely feasible assignments. Removed; the Rust revision is
  now a pure outward-rounded forward check.
- **`eigendecomposition_split` hard-imported NumPy.** Replaced with a dependency-free
  cyclic Jacobi eigensolver; `eigendecomposition_split`/`eigendecomposition_factors`
  both work without any optional extra.
- **`pattern.py` raised `UnsupportedPattern` for `\b`/`\B`** even though word-boundary
  masking is legal. They are now zero-width *conditional* edges resolved against the actual
  previous/next character (end-of-string counts as non-word), verified exact against
  `re.search` on exhaustive small-alphabet inputs (satisfaction and infeasible-prefix
  soundness). Word-boundary patterns join the exhaustive-mask test corpus.
- **Kohler's pruning in the Fourier–Motzkin solvers could flip UNSAT → SAT/UNKNOWN.**
  Demonstrated on an 8-row infeasible system: the lineage-size rule drops the only
  refutation combination. Replaced (Python `nano_solver` and Rust `solver`) with
  *subsumption* — rows in sign-normalised buckets, keep the strongest bound per bucket;
  sound by implication. Added regression tests on both sides.
- **Git committed 329 build artifacts** (`target/`, `python/veritas/veritas_py.so`, a root
  symlink) — removed from the index and `.gitignore`d.

## Horizon 1 — speed & caching

- Rust `VocabularyTrie` rebuilt as a structured PDA-driven depth-first traversal: one Rust
  call returns the *whole* allowed-token set (or a packed `u64` bitset, `mask_bitset`)
  without cloning the tokenizer vocabulary per decoding step.
- Python `TokenMasker` caches by a canonical PDA signature (stack shape + seen-key hash +
  pending number/string state) instead of the raw prefix.
- Rust FM elimination keeps provenance as a `u64` bitmask for exact `unsat_core` lineage.

## Horizon 2 — per-field KL-distortion receipts

- At each sampled step the distortion introduced by hard masking is exactly
  `−log(P_raw(allowed))`. Tracked per field and per step (`DecodeTelemetry.field_kl_divergence`,
  `kl_distortion_tokens`).
- `result.receipt()` (both `DecodeResult` and `generate()`'s `VerifiedResult`) returns a
  self-contained audit record: SHA-256 of the raw text, spec digest, verification status,
  attempts, backtracks, jump-forward counters and the per-field KL divergence.

## Horizon 3 — agentic ecosystem

- **`veritas serve`** — OpenAI-compatible reverse proxy in front of an upstream LLM.
  Non-streaming `/v1/chat/completions` responses are re-verified against a `@vt.verified_schema`
  before the client sees them: `422 veritas_verification_failed` on violation, otherwise the
  completion is returned with a `veritas_certificate` attached. Streaming (SSE) forwards
  token-by-token and injects a `data: {"veritas_certificate": ...}` event before `[DONE]`
  (chunked framing, hold-back of the terminator).
- **`veritas export-rl`** — decoder conflict traces (`DecodeConfig(rl_trace_path=...)`)
  become TRL-ready preference data: DPO shared-prefix pairs or dense per-step GRPO rewards,
  with counts and SHA-256 manifests.
- **`vt.VeritasMcpSession` / `@session.verified_tool`** — the MCP firewall. LTLf temporal
  masking (`session.allowed_tools()`), env binding across turns (`last_order_total`,
  `<tool>.<key>`), accumulation counters (`refunded`, `total_cost`, …), per-call spend caps
  and budgets, taint tracking (`UntrustedString` + pydantic-native validation),
  `requires_taint_free` blocking, and `on_violation=raise|return`.
- **`veritas.explain-unsat`** — minimal relaxation wizard: per core constraint, the smallest
  additive slack that repairs the system, or "this is structural" when no single clause fixes
  it. Also reports exact 1-D bound conflicts (transpiler-tightened field bounds).
- **Adaptive `<|solver_feedback|>` reflex** (`DecodeConfig(reflex_on_backtrack=True)`) — on
  CDCL jumpback a *bounded* CRANE scratchpad re-opens, seeded with the algebraic conflict
  (field, reason, domain cut). The span is appended to `result.reasoning` only — never to
  the decoded JSON — with explicit markers so a downstream agent loop can lift it verbatim.

## Known limitations, honestly

- `veritas serve` is a *monitor* for streaming traffic — token chunks cannot be un-emitted;
  hard enforcement is available for the non-streaming path (`422` before the client's buffer
  fills).
- `explain-unsat` computes single-clause minimal deltas by bisection; joint relaxation is
  reported but not optimized globally.
- The relaxation wizard probes Fourier–Motzkin directly, so very large cores return status
  reports rather than deltas (`>12` variables).
- The 1.5 milestone ships no live LLM benchmark harness in-repo; `benchmarks/decode_smoke.py`
  and `benchmarks/native_speedup.py` cover the reference engine deterministically.
